# Bonnington — Phase 2: Tracker Design

Date: 2026-11-15
Status: approved in conversation ("build next"); calls marked *(my call)* were not discussed
Builds on: `2026-11-15-bonnington-voice-design.md`

## Intent

Bonnington keeps track of the user's academic and personal life and their coding projects, so he can answer "what's left this week?" and roast with facts. He is a **tracker, not a study companion**.

## Goals

- Record what the user tells him by voice: exams, assignments, scores, tasks.
- Sort it into **Academic**, **Personal** and **Projects**.
- Keep a short running summary ("gist") per subject: what's coming up, scores so far.
- Know which coding projects are in progress, from Claude Code's local history, read-only.
- Answer status questions from the stored data only.

## Non-goals

- Answering academic/subject questions, quizzing, holding syllabus or lecture notes. He refuses in character.
- Speaking first (morning summary, exam-eve nudge). **Open item for later.**
- A calendar screen in the window.
- Search by meaning / embeddings.

## Anti-goals

- Inventing facts. Everything he states about the user's schedule, scores or projects comes from the vault or the project scan.
- Anything leaving the machine. Claude Code history is only read from local files.
- Writing to the user's project folders or to `~/.claude`.

## Approaches considered

1. **Markdown vault, one strict line per item, derived files regenerated by code.** ← chosen. The user can open and fix it (Obsidian, any editor); the code parses it back; no database.
2. **SQLite, voice-only edits.** Simpler to build, but every correction has to go through speech recognition, which is imperfect.
3. **Free-form notes + search by meaning.** Needed only for a study companion; rejected with that scope.

## Design

### Vault (default `data/vault/`, setting `vault_dir`)

```
Academic/Exams.md         - [ ] 2026-11-24 09:00 | DBMS | Midterm 2 | units 3-5
Academic/Assignments.md   - [ ] 2026-11-20 | CN | Lab report 3
Academic/Scores.md        - 2026-11-10 | DBMS | Midterm 1 | 38/50
Academic/Subjects/DBMS.md (generated gist)
Personal/Tasks.md         - [ ] Renew passport | due 2026-12-01
Projects/medrag.md        user notes; `status: on hold` line optional
Calendar.md               (generated) every dated open item, soonest first
```

- Source files are the user's to edit. A line that doesn't parse is kept as-is and ignored by the tracker, never deleted.
- Generated files (`Subjects/*.md`, `Calendar.md`) carry a "generated, edits are overwritten" header and are rebuilt after every change.
- Done items are ticked `- [x]`, not removed.

### Saving by voice *(my call)*

He saves straight away, then **reads back exactly what he filed** ("Filed. DBMS exam, Tuesday the 24th, nine a.m."). "No, that's wrong" → an **undo** tool removes the last change. This is more reliable with a small local model than a two-step "confirm before saving" dialogue.

### Dates *(my call)*

The model passes dates as the user said them ("next Thursday", "the 24th", "24 Nov", "tomorrow"). Code resolves them against today's date; an unresolvable date is an error returned to the model, which asks the user again. Day-of-month with no month means the next such day.

### Projects

- Scan `~/.claude/projects/*/*.jsonl` (setting `claude_projects_dir`): project folder (`cwd`), newest session time, latest session title, git branch.
- Only folders under the user's projects root (setting `projects_root`, default `C:\Users\work\work`); worktrees, scratchpads and temp folders are skipped; sessions are grouped by project folder.
- State from last activity *(my call)*: **active** ≤ 7 days, **stalled** ≤ 30 days, **cold** beyond.
- Area: path under a folder named in `academic_folders` (default `["clg"]`) → Academic; otherwise Personal.
- The user can tell him a project is `on hold` or `done`; that goes in `Projects/<name>.md` and stops the nagging.

### Brain

- **Snapshot every turn** *(my call)*: today's date, the next 7 days of dated items, overdue items, open task count, recent scores, and project states go into the system message. Common questions ("what's left this week?") need no tool call, so they stay fast.
- **Tools** (Ollama tool calling, gemma4:12b): `add_exam`, `add_assignment`, `add_task`, `add_score`, `mark_done`, `remove_item`, `undo_last`, `list_items`, `subject_summary`, `project_status`, `set_project_status`.
- Tool turns cost a second model call (~1 s extra).
- Persona additions: he now has the user's data; uses only it; refuses subject questions in character; reads back what he filed.
